# Терминал: автоматический REST-сервис (стандартный интерфейс OData)

Инструкция по настройке стандартного интерфейса OData для подключения внешнего
терминала (кассы, мобильного приложения, стороннего сервиса) к информационной базе
1С/БАС по протоколу REST.

**Файл модуля:** `OData_StdInterface_Settings_NoConst.bsl`

---

## Зачем нужен этот патч

Типовой механизм БСП хранит ссылку на служебного пользователя REST-сервиса
в константе `Константы.ПользовательСтандартногоИнтерфейсаOData`.

В **базовых версиях** конфигураций добавлять новые константы нельзя. Патч заменяет
константу на элемент справочника `Константа` с наименованием
`ПользовательСтандартногоИнтерфейсаOData` — справочник в базовых версиях
редактировать можно.

| Было (типовой БСП) | Стало (этот патч) |
|---|---|
| `Константы.ПользовательСтандартногоИнтерфейсаOData.Получить()` | `ПолучитьПользователяODataИзСправочника()` |
| `Константы.ПользовательСтандартногоИнтерфейсаOData.Установить(...)` | `СохранитьПользователяODataВСправочник(...)` |

---

## Предпосылки

- Конфигурация на БСП с подсистемой «Стандартный интерфейс OData».
- Роль `УдаленныйДоступOData` присутствует в конфигурации.
- Справочник `Константа` существует в конфигурации.
- Право `АдминистрированиеДанных` у пользователя, выполняющего настройку.
- **Резервная копия информационной базы.**

---

## Шаг 1. Подготовить справочник «Константа»

Патч умеет работать в двух режимах — выберите один:

**Вариант А (рекомендуемый).** Добавьте в справочник `Константа` реквизит:

| Реквизит | Тип | Назначение |
|---|---|---|
| `Пользователь` | `СправочникСсылка.Пользователи` | Ссылка на служебного пользователя REST-сервиса |

Функция `ЕстьРеквизитСправочникаКонстанта("Пользователь")` определит наличие
реквизита по метаданным и будет использовать его.

**Вариант Б.** Не добавлять реквизит вовсе — тогда ссылка сохранится
в `ДополнительныеСвойства` объекта.

> ⚠ Вариант Б **не сохраняет значение между сеансами**: `ДополнительныеСвойства` —
> это свойство объекта в памяти, оно не записывается в базу. Используйте вариант Б
> только как временную заглушку, для рабочей эксплуатации нужен вариант А.

---

## Шаг 2. Разместить код

Перенесите содержимое `OData_StdInterface_Settings_NoConst.bsl` в общий модуль,
где расположены типовые процедуры настройки OData (обычно
`ИнтеграцияOData` / `СтандартныйИнтерфейсOData` — имя зависит от версии БСП).

Заменяемые процедуры и функции:

| Метод | Назначение |
|---|---|
| `РольДляСтандартногоИнтерфейсаOData()` | Возвращает роль `УдаленныйДоступOData` |
| `ПроверитьВозможностьСозданияПользователяДляВызововСтандартногоИнтерфейсаOData()` | Проверяет, что в базе есть хотя бы один пользователь |
| `ЕстьРеквизитСправочникаКонстанта(ИмяРеквизита)` | Проверяет состав реквизитов справочника по метаданным |
| `ПолучитьПользователяODataИзСправочника()` | Читает ссылку на служебного пользователя |
| `СохранитьПользователяODataВСправочник(СсылкаПользователя)` | Записывает ссылку, создавая элемент при необходимости |
| `СвойстваПользователяСтандартногоИнтерфейсаOData()` | Возвращает структуру: Пользователь, Идентификатор, Имя, Аутентификация |
| `ЗаписатьНастройкиАвторизацииДляСтандартногоИнтерфейсаOData(НастройкиАвторизации)` | Включает/выключает авторизацию REST-сервиса |

---

## Шаг 3. Включить публикацию OData

1. Конфигуратор → «Администрирование» → «Публикация на веб-сервере».
2. Включить флажок **«Публиковать стандартный интерфейс OData»**.
3. Опубликовать базу, запомнить адрес публикации.

---

## Шаг 4. Включить авторизацию REST-сервиса

Вызов из пользовательского режима (обработка настройки или консоль):

```1c
НастройкиАвторизации = Новый Структура;
НастройкиАвторизации.Вставить("Используется", Истина);
НастройкиАвторизации.Вставить("Логин", "odata_terminal");
НастройкиАвторизации.Вставить("Пароль", "<надёжный пароль>");

ЗаписатьНастройкиАвторизацииДляСтандартногоИнтерфейсаOData(НастройкиАвторизации);
```

Процедура выполнит в одной транзакции:
1. Проверит право `АдминистрированиеДанных` и наличие пользователей в базе.
2. Создаст (или обновит) элемент справочника `Пользователи` с наименованием
   «Автоматический REST-сервис», признаком `Служебный` и ролью `УдаленныйДоступOData`.
3. Создаст пользователя информационной базы со стандартной аутентификацией
   и запретом смены пароля.
4. Сохранит ссылку в элемент справочника `Константа`.
5. Запишет результат в журнал регистрации.

**Отключение авторизации:**

```1c
НастройкиАвторизации = Новый Структура("Используется", Ложь);
ЗаписатьНастройкиАвторизацииДляСтандартногоИнтерфейсаOData(НастройкиАвторизации);
```

При отключении пользователю ИБ запрещается вход (`ВходВПрограммуРазрешен = Ложь`),
но ссылка в справочнике `Константа` сохраняется как история выбора.
Очистите элемент вручную, если нужно полностью удалить настройку.

---

## Шаг 5. Открыть состав объектов для терминала

По умолчанию через OData не доступен ни один объект. Откройте только то, что нужно терминалу:

«Администрирование» → «Настройка состава стандартного интерфейса OData» →
отметить нужные справочники и документы.

> Открывайте минимально необходимый состав объектов — стандартный интерфейс OData
> даёт полный доступ на чтение и запись к каждому опубликованному объекту.

---

## Шаг 6. Проверить подключение

```
GET https://<сервер>/<база>/odata/standard.odata/$metadata?$format=json
```

Авторизация — Basic, логин и пароль из шага 4.

Пример чтения справочника:

```
GET https://<сервер>/<база>/odata/standard.odata/Catalog_Номенклатура?$format=json&$top=10
```

## Проверка настройки из кода

```1c
Свойства = СвойстваПользователяСтандартногоИнтерфейсаOData();

Сообщить("Пользователь: " + Строка(Свойства.Пользователь));
Сообщить("Имя пользователя ИБ: " + Свойства.Имя);
Сообщить("Стандартная аутентификация: " + Строка(Свойства.Аутентификация));
```

Если `Свойства.Пользователь` пустой — ссылка не сохранилась. Проверьте:
- существует ли элемент справочника `Константа` с наименованием
  `ПользовательСтандартногоИнтерфейсаOData`;
- добавлен ли реквизит `Пользователь` (см. шаг 1, вариант А).

## Исправленные ошибки в этом модуле

| Что было | Почему не работало | Как исправлено |
|---|---|---|
| `Объект.Свойство("Пользователь")` для объекта справочника | `Свойство()` — метод структуры, у `СправочникОбъект` его нет: «Метод объекта не обнаружен» | Проверка состава по метаданным: `Метаданные.Справочники.Константа.Реквизиты.Найти(...)` |
| `НСтр("ru='текст'" + "\n\nдалее" + ...)` | Конкатенация разрывает формат строки локализации, а `\n` в языке 1С не является escape-последовательностью — в текст попадали символы `\n` | Многострочный литерал внутри `ru='...'` с продолжением через `\|` |
| Чтение реквизита через `Элемент.ПолучитьОбъект()` до проверки метаданных | Лишняя загрузка объекта и исключение при отсутствии реквизита | Реквизит читается прямо из ссылки, объект загружается только для резервного варианта |

## Диагностика

| Симптом | Причина | Решение |
|---|---|---|
| «Недостаточно прав доступа для настройки автоматического REST-сервиса» | Нет права `АдминистрированиеДанных` | Выполнять под администратором |
| «Нельзя создать отдельные логин и пароль… отсутствуют другие пользователи» | В базе нет ни одного пользователя ИБ | Создать администратора в списке пользователей |
| HTTP 401 при запросе к OData | Неверные логин/пароль либо авторизация выключена | Повторить шаг 4 |
| HTTP 404 на `$metadata` | Не включена публикация стандартного интерфейса OData | Шаг 3 |
| В `$metadata` нет нужного объекта | Объект не включён в состав интерфейса | Шаг 5 |
| Настройка «слетает» после перезапуска | Использован вариант Б без реквизита `Пользователь` | Добавить реквизит (шаг 1, вариант А) |

Подробности любой неудачной попытки записи пишутся в журнал регистрации,
событие «Настройка стандартного интерфейса OData.Запись пользователя».

---

## Безопасность

- Служебному пользователю выдаётся **только** роль `УдаленныйДоступOData`.
- Пользователь создаётся с признаком `Служебный` и скрыт из списка выбора.
- Смена пароля пользователем запрещена (`ЗапрещеноИзменятьПароль`).
- Пароль не попадает в журнал регистрации — он удаляется из описания перед записью.
- Публикуйте OData только по HTTPS: Basic-авторизация передаёт пароль в открытом виде.
